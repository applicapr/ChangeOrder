### Audit & Soft-Delete Impact *(mandatory when feature touches persisted entities)*

Per `.specify/memory/constitution.md` v1.0.0 Principle IV, any feature that creates, updates, or deletes persisted records MUST address the following before approval:

- **AS-001**: Entities introduced or modified MUST implement `ISoftDeletable` + `IAuditable`. Manual writes to `CreatedAt`/`UpdatedAt`/`DeletedAt`/`IsDeleted` outside `AuditInterceptor` are prohibited.
- **AS-002**: New unique business identifiers (natural keys) MUST be enforced by a UNIQUE database constraint, not application code alone.
- **AS-003**: Read paths MUST honor the global `HasQueryFilter` for soft delete; any intentional bypass MUST be justified here.
- **AS-004**: If this feature exposes a `DELETE` endpoint, confirm the operation is a soft delete (sets `IsDeleted=true`, `DeletedAt=UtcNow`) and NOT a physical row removal.

If the feature does NOT touch persisted entities, write a single line: `N/A — feature is read-only / non-persistent.`
